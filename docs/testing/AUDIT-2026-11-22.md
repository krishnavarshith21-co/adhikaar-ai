## G. Remaining issues and blockers

1. **High — Java eligibility integration:** dashboard/recommendations/assistant use the TypeScript preliminary engine. The separate Java database rule engine is unit-tested but its controller is denied by current security configuration and not called by the frontend. Full Java authority/parity is not delivered; enabling it without reconciling its rule database would misrepresent coverage. No LLM-based decisions were introduced.
2. **High — full voice demonstration:** Gemini speech quota failure; no live microphone accuracy or audible quality evaluation. Obtain quota and run the requested physical phrases on actual devices before presenting voice as verified.
3. **High — production data/deployment:** PostgreSQL/Flyway and restart durability unverified. H2 tests are not PostgreSQL certification. Java workspace accepts broadly shaped JSON rather than a complete domain schema; direct authenticated callers can store malformed own-account workspace data. Frontend mutations validate their own payloads, but backend schema validation needs strengthening before a pilot.
4. **High — production authentication hardening:** no proven login/registration brute-force control, no distributed rate limiter/session store, and no real password recovery delivery service. Eight-hour in-memory sessions are unsuitable for a multi-instance production deployment. TLS/reverse-proxy/cookie configuration needs deployment-specific verification.
5. **Medium — missing requested capabilities:** state/provider/NGO filters, broad spelling correction, district/education/gender/category inputs, tri-state Preflight, required/optional document metadata, six-stage application tracking, notification links/preferences/delivery, and dashboard language switcher are absent. Current four-stage personal preparation tracking deliberately makes no government submission claims.
6. **Medium — localisation/accessibility coverage:** dashboard and many labels/errors remain English. Public informational page bodies are not all translated. Human Hindi/Telugu translation review, screen-reader coverage, contrast calculations, modal focus restoration and full WCAG audit remain outstanding.
7. **Medium — live grounded AI:** provider connectivity passed in two languages, but this was supplied application-description evidence, not an authenticated live scheme retrieval conversation. Retrieval redirects/outages, evidence-validator false negatives and all requested real questions need dedicated live testing. Citation validation tests pass; they do not prove factual correctness.
8. **Not tested environments:** Safari, Firefox, Edge, iOS, Android, real Retina hardware, physical microphones/speakers, production networking and load/latency/heap metrics. Chrome DPR and touch emulation are not device certification.
9. **Maintenance:** unused legacy `src/lib/data.ts`, `src/lib/types.ts` and older server/Java integration code were observed; no mass deletion performed. Two extraneous npm packages remain. Existing verification scripts outside the new audit suites contain old provider assumptions and should not be treated as current certification.
10. **Owner action — previously exposed OpenAI key:** rotate/revoke the key reported exposed in prior chat through the provider account. No key value was displayed or copied into this report. `.env.local` is ignored; scanning the built client JavaScript found zero occurrences of configured API-key values. This does not prove the historically exposed key was revoked.
